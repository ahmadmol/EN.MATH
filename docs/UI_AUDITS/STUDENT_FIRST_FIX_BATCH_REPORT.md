## 2. المشاكل التي أُصلحت والأدلة (Fixed Issues & Evidence)

### 1) AUD-05 — Assignment Submission Result
- **المشكلة:** كان النظام ينتقل إلى شاشة النتيجة `assignments/{id}/result` حتى إذا فشل الحفظ أو رُفض التسليم (بسبب تجاوز الموعد أو استنفاد المحاولات أو كون المستخدم ضيفًا)، مما يتسبب إما في عرض نتيجة قديمة أو شاشة فارغة وفقدان إجابات الطالب صامتًا.
- **الإصلاح:**
  - اعتماد `AssignmentSubmissionResult` نتيجة صريحة للتسليم.
  - الحفظ والانتقال لشاشة النتيجة يحدثان فقط عند `Submitted`.
  - عند الرفض، يبقى الطالب في الواجهة مع عرض شريط توضيحي بالسبب وإبقاء إجاباته محفوظة للتحقق.
  - منع الضغط المتكرر المزدوج أثناء معالجة التسليم.
- **الأدلة:** نجاح الاختبار `assignmentSubmissionReturnsExplicitResultAndSavesOnlyOnSuccess` في `StudentFirstFixBatchTest.kt`.

### 2) AUD-07 — Screen Titles & Navigation Metadata
- **المشكلة:** الوجهات العميقة (`gems/wallet`, `gems/review`, `study/catalog`) كانت تعرض العنوان "EN.MATH" في الهيدر العلوي لعدم وجود تعريف صريح لها في `topTitle`.
- **الإصلاح:**
  - إضافة عناوين صريحة ومترجمة لكل وجهة عميقة.
  - المحافظة على زر الرجوع والعودة للوجهة السابقة دون التأثير على شريط الهيدر الرئيسي المعتمد للرئيسية.
- **الأدلة:** اختبار `routesSelectedTabMapsDeepDestinationsToParentTabs` ومراجعة `ENMathApp.kt`.

### 3) AUD-08 — Navigation Rail Mapping
- **المشكلة:** عند فتح التطبيق على الشاشات الواسعة (أكبر من أو تساوي 768dp)، كانت وجهة المختبر `"explore"` تظهر باسم "حسابي" وأيقونة الشخص لتخلفها عن `tabLabel` و `tabIcon`.
- **الإصلاح:**
  - إضافة mapping صريح لـ `"explore"` يربط الاسم بـ "استكشاف" والأيقونة بـ `Icons.AutoMirrored.Outlined.ShowChart`.
  - المحافظة الكاملة على المسارات (Routes) و Test Tags والتنقل السفلي للهاتف دون تغيير.
- **الأدلة:** مطابقة `ENMathApp.kt` واختبارات التناظر.

### 4) AUD-12 — Weekly Gems Eligibility Text
- **المشكلة:** بطاقة المراجعة الأسبوعية كانت توضح نصًا غير دقيق ("تتوفر بعد إكمال درسين وتوفر ٥ أسئلة مؤهلة")، بينما كود السياسة الحقيقية `LocalLearningGems.weekly()` يشترط ٥ دروس موثقة مميزة ذات نقاط تحقق.
- **الإصلاح:**
  - ربط نص البطاقة بمصدر الحقيقة `LocalLearningGems`.
  - حساب عدد الدروس الموثقة المتبقية ديناميكيًا وعرضها للطالب بوضوح دون تغيير قواعد كسب الجواهر أو أعداد الأسئلة.
- **الأدلة:** اختبار `weeklyGemsRequiresFiveCompletedVerifiedLessons`.

## 6. خطة معالجة AUD-01 و AUD-03 المستقلة (Separate Strategy & Migration Plan)

### أ. خطة AUD-01 — استراتيجية عزل الحسابات وترحيل البيانات غير الهدام
1. **الهدف:** عزل تقدم التعلم لكل طالب (الدروس المكتملة، الواجبات، المحاولات، الإشارات المرجعية) حسب بريد الحساب (`owner`) لمنع تسرب بيانات حساب طالب إلى آخر.
2. **الاستراتيجية غير الهدامة:**
   - مفاتيح التخزين المحلي تُربط بمعرّف الحساب الموحد (مثال: `student_progress_${ownerHash}`).
   - عند أول تشغيل بعد التحديث، إذا وجد تقدم سابق في المخزن العام ولم يُنسب لحساب بعد، يُنسخ (ولا يُحذف) إلى الحساب النشط الحالي كنسخة أولية.
   - إبقاء التخزين القديم متاحًا كنسخة احتياطية للقراءة فقط لضمان إمكانية الاستعادة.
3. **اختبارات التعافي (Recovery Tests):**
   - كتابة اختبارات وحدة للـ Codec تعاير التبديل بين الحسابات المختلفة وتتحقق من عدم تداخل البيانات.
   - اختبار سيناريو تسجيل الخروج والدخول بحساب مختلف والتأكد من استعادة بيانات كل حساب بدقة.

### ب. خطة AUD-03 — استراتيجية تعافي التخزين والـ JSON غير الهدامة
1. **الهدف:** معالجة حالات فساد ملفات JSON أو تضارب النسخ دون استبدال بيانات الطالب صامتًا بالقيم الافتراضية (Demo/Seed).
2. **الاستراتيجية غير الهدامة:**
   - استخدام كتابة آمنة (Atomic Write: الكتابة لملف مؤقت ثم التبديل).
   - تغليف حالة التخزين بغلاف ذي رقم إصدار (Schema Version Envelope).
   - عند فشل تحليل الـ JSON، لا يُمس الملف الأصلي، بل يُحفظ باسم احتياطي (مثال: `state_corrupted_backup.json`) وتُرجع حالة صريحة `LoadResult.Corrupted(rawJson, exception)`.
   - إتاحة زر استعادة محلي للطالب أو خيار محاولة إصلاح تلقائي غير هدام.
3. **اختبارات التعافي (Recovery Tests):**
   - تقديم نصوص JSON مشوهة أو غير مكتملة واختبار عدم مسح الملف واسترجاع النسخة الاحتياطية بنجاح.
